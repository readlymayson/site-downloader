# Site Downloader — массовое скачивание документации в текст для LLM/RAG

Скачивает документацию целого портала (по `sitemap.xml` или списку URL), вытаскивает чистый текст и складывает его в структуру, пригодную для обучения и индексации нейросетей.

---

## Проблема

Чтобы нейросеть отвечала по документации продукта, эту документацию сначала надо собрать в текстовом виде. Вручную это нереально:

- документация amoCRM, Wazzup или любого вендорского API — это **сотни страниц** с деревом навигации;
- копировать страницы руками — дни работы и постоянно пропущенные разделы;
- обычный `wget` тянет HTML вместе с меню, рекламой и скриптами — в таком виде текст для LLM мусорный;
- склеить всё в один файл «для контекста» тоже нужно автоматически.

## Что делает

| Задача | Как решается |
|---|---|
| Скачать весь портал | `--sitemap` — находит `sitemap.xml` и обходит все страницы |
| Скачать конкретный раздел | `--section-prefix /developers/content/` — фильтр по пути |
| Скачать по своему списку | `--urls` или `--file urls.txt` |
| Добавить страницы, которых нет в sitemap | `scripts/collect_links.py` — вытаскивает ссылки из HTML-дерева навигации по CSS-селектору |
| Получить чистый текст | `trafilatura` (основной метод), `BeautifulSoup + lxml` (резерв) — реклама, меню и скрипты удаляются |
| Подготовить файл для LLM | `--combine` — один большой `combined_docs.txt` со всей документацией |
| Ускорить обход | `--workers N` — многопоточное скачивание |

Дополнительно: уже скачанные страницы не тянутся повторно, ошибки по отдельным страницам не останавливают обход, в конце выводится статистика.

## Архитектура

```
docs_downloader.py            # основной движок: обход, скачивание, извлечение текста, запись
scripts/collect_links.py      # сбор URL из дерева навигации (CSS-селектор) → файл со ссылками
requirements_docs_downloader.txt
example_urls.txt              # образец списка URL
```

Поток обработки:

```
источник URL                скачивание              извлечение            запись
──────────────              ──────────              ──────────            ──────
sitemap.xml      ┐
--urls / --file  ├─►  пул потоков (--workers)  ─►  trafilatura  ─┬─►  <output>/<page>.txt
collect_links.py ┘                                  (fallback:   └─►  combined_docs.txt (--combine)
                                                     bs4 + lxml)
```

Ключевые решения:

- **Два независимых источника URL** — `sitemap.xml` покрывает «официальные» страницы, `collect_links.py` добирает то, что в sitemap не попало (документация часто собирается из навигационного дерева).
- **Два экстрактора с деградацией** — если `trafilatura` недоступна, скрипт не падает, а переключается на `BeautifulSoup`; предупреждение печатается один раз при старте.
- **Идемпотентность** — наличие файла на диске = страница обработана, повторный запуск продолжает с места остановки.
- **Отказоустойчивость на уровне страницы** — сбой одной страницы не роняет весь обход.

## Результат

- Документация **amoCRM** и **Wazzup** собрана в текст и готова к загрузке в LLM/RAG (кейсы, под которые инструмент и писался).
- Вместо дней ручного копирования — один запуск команды и ожидание обхода.
- На выходе: по одному `.txt` на страницу + опциональный объединённый файл; текст без навигации и рекламы, с сохранением абзацев и списков.
- Инструмент **переиспользуемый**: смена `--selector`, `--base-url` и `--prefix` переносит пайплайн на любой другой портал с деревом документации.

## Стек

`Python 3.8+` · `requests` · `trafilatura` · `BeautifulSoup4` + `lxml` · `ThreadPoolExecutor` · `xml.etree.ElementTree` · `argparse`

## Быстрый старт

```bash
pip install -r requirements_docs_downloader.txt
```

**1. Весь портал через sitemap + один общий файл:**

```bash
python docs_downloader.py --sitemap https://docs.example.com --combine
```

**2. Конкретный раздел:**

```bash
python docs_downloader.py --sitemap https://www.amocrm.ru/developers/content/ \
  --section-prefix /developers/content/
```

**3. Ссылки из дерева навигации (когда sitemap не покрывает нужное):**

```bash
python scripts/collect_links.py \
  --source tree_amocrm_docs \
  --selector ".nav_aside__list a" \
  --base-url https://www.amocrm.ru \
  --prefix /developers/content/ \
  --output amocrm_links.txt

python docs_downloader.py --file amocrm_links.txt --output amocrm_docs
```

### Параметры

| Параметр | Описание |
|---|---|
| `--urls`, `-u` | Список URL для скачивания |
| `--sitemap`, `-s` | Базовый URL для поиска `sitemap.xml` |
| `--section-prefix` | Фильтр по префиксу пути (например `/developers/content/`) |
| `--file`, `-f` | Файл со списком URL (по одному в строке) |
| `--output`, `-o` | Директория сохранения (по умолчанию `downloaded_docs`) |
| `--workers`, `-w` | Количество потоков (по умолчанию 5) |
| `--combine`, `-c` | Собрать всю документацию в один файл |

## Формат вывода

```
downloaded_docs/
├── page-1.txt
├── page-2.txt
└── ...
combined_docs.txt      # при --combine
```

Каждая страница — отдельный `.txt` с очищенным текстом; при `--combine` дополнительно создаётся объединённый файл.

## Ограничения

- Сайты, полностью рендерящиеся JavaScript, требуют Selenium — в базовую версию не входит.
- Sitemap может не содержать часть страниц (лечится `collect_links.py` или `--file`).
- Скрипт не обходит `robots.txt` и не решает вопросы авторских прав — соблюдение правил сайта на стороне пользователя.

## Лицензия

Свободное использование. Убедитесь, что соблюдаете правила использования сайтов и авторские права.
